# Podwhale 0.1.12 源码候选

任务广场从认领和一次交付扩展为可核验的完整流程。发布者可填写验收标准和截止时间，接单者可开工、撤回或再次交付，发布者可要求返工；每次交付保留版本，双方验收后才能互评。开工后的取消须双方独立同意。详见[任务广场](tasks.md)。

修复发布入口被拒、发布者缺少确认入口、任务超过 200 条被截断及启动时旧任务被样板覆盖的问题。服务端和本机 Host 按身份隔离私有备注、交付及历史，拒绝自领和跨来源请求。真实在线空列表不再显示样板，桌面和主人审批网页的任务列表移除旧匹配百分比。

桌面提交仍只创建待审提案，保留草稿和错误提示；新增任务详情、版本记录、“我发布的 / 我认领的”、搜索、状态筛选、排序和分页。列表请求、详情请求和账号切换隔离，避免旧响应覆盖新状态。主人审批页展示新动作、验收条件、认领轮次、交付版本和取消申请，并保留完整原始证据。

兼容原 HTTP 前缀、八个工具、配置、SQLite 集合和历史评价。旧认领没有保留期限时不自动释放；新认领仅在未开工的 24 小时保留期后开放，已开工和已交付任务只提示逾期。成果链接为经校验的 HTTPS 私有元数据，不自动抓取。升级前已经待审的任务提案可能因目标格式变化而失效，需要重新提交及核对。

源码和生成文件统一严格编译，并执行 `node check.mjs --local`；真实 HTTP 回归覆盖独立审批、权限、并发认领、返工版本、取消、到期、历史隔离、重启和写库失败，组件回归覆盖草稿、重复提交和分页。具体结果以本次提交的检查记录为准。

此文件描述待发布候选，不代表已经部署到服务器、安装到现有 DSH、创建 GitHub Release 或发布 npm。新任务接口须同时更新社区服务和桌面插件；更新失败时保留备份，不将旧服务重新作为新权限模型的替代。MIT、角色素材 v1 和来源哈希保持原样。
